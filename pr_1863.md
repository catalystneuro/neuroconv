# Install CI with uv, name the minimum and maximum Python versions, and stop sleeping on the DANDI sandbox

With the test-time work done, installing is what a job mostly does: on ubuntu the full pytest step is 5m27s of a 13m22s job, while the six isolated-extras environments cost 3m53s and the base install another 1m08s, all of it creating virtual environments and resolving from scratch with no pip cache anywhere in the repository, so this moves every install in `testing.yml` to uv, following the pattern `formatwise-installation-testing.yml` already runs on all four operating systems. I left `setup-uv`'s cross-run cache off on purpose: those six steps exist to prove each extras group installs on a machine that has nothing, and a wheel served from a cache GitHub restored is not a download that happened today, which locally is worth about ten seconds a job against the three to four minutes uv itself saves. While in there I gave the Python support range names: `min_python_version.txt` and `max_python_version.txt` replace `all_python_versions.txt` and the workflows compose the full list from them, which matters because the minimum was previously a bare `"3.10"` repeated in three ternaries and could silently drift from `requires-python`, so a test now asserts the two agree. That also gives the live-service tests something to key on. They exercise DANDI, EMBER and Globus network behavior rather than anything platform-specific, and the dev dailies already run the full matrix every night, so a pull request now runs them on every operating system but only the newest Python, halving that group and freeing two macOS runner slots per push. Last, the YAML upload test waited on the sandbox with a flat `time.sleep(60)` that was 40 percent of that job's runtime; it now polls until the sandbox reports the assets this run uploaded, which returns as soon as the server is ready and fails the same way if it never is.
