`add_sorting_analyzer_to_nwbfile` and `write_sorting_analyzer_to_nwbfile` now write every computed extension of the analyzer (waveforms, templates, principal components, correlograms, metrics, ...) with [ndx-spikesorting](https://github.com/catalystneuro/ndx-spikesorting) when ndx-spikesorting>=0.1.2 is installed, so `ndx_spikesorting.read_sorting_analyzer_from_nwb` can read the analyzer back. The units table keeps its metric columns, with `firing_rate` and `num_spikes` written as the extension's typed columns. This is controlled by the new `use_ndx_spikesorting`: by default the extension is used when it can be, with a warning when it cannot (a multi-segment analyzer), `True` raises in that case, and `False` writes the units table only, as before. Linking the recording is optional: the new `electrical_series_name` gives the path of the ElectricalSeries the analyzer was computed on (e.g. `"acquisition/ElectricalSeries"`), and `write_sorting_analyzer_to_nwbfile` links the series it writes with `write_electrical_series=True`. Without one, the analyzer reads back without a recording. The default backend configuration now also chunks and compresses datasets that extension types hold as a `VectorData`, such as ndx-spikesorting's waveforms.
