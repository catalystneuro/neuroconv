# Read MedPC events into `EventsTable` and deprecate `MedPCInterface`

MedPC is the last interface writing `ndx-events`, so this is the interface side of getting that dependency out. `MedPCInterface` is deprecated for August 2027 rather than rewritten in place, since the written file changes either way and a conversion in flight should keep running until its author moves it.

What replaces it is two interfaces rather than one, and the split is on where an event type's identity comes from, because that is what changes the read path. `MedPCArrayEventsInterface` reads a file that holds one lettered array per event type, which is the layout the deprecated interface read; `MedPCCodedEventsInterface` reads a file that carries the identity in the data, either packed into the time value or in a companion array of codes. How a stored value becomes a time is a second, orthogonal question, and it is shared parameters on both rather than more classes: `time_unit`, `clock_ticks_per_second` and `relative_mode`, the last being Med Associates' own term for a program that stored the interval since the previous event rather than the elapsed time. Splitting on both axes instead would have multiplied into a fifteen-class matrix for what is two read paths and a transform.

The reason for that much configuration is that MedPC records none of it. The manual defines `DISKVARS`, `DISKFORMAT`, `DISKCOLUMNS` and `DISKOPTIONS`, all of which govern how a number is printed, and nothing that says what a number means; the ten header fields MED-PC IV writes carry no unit, no clock resolution and no mode. All of that lives in the MSN program the experimenter wrote, which a published dataset usually does not ship. Every way of getting it wrong therefore decodes without error and produces a plausible-looking file with wrong timestamps, which is the worst outcome for archived data, so both interfaces check two things the file can answer: that onsets never run backwards, and that no event falls after the session the header itself delimits. Neither check alone is enough, since accumulating intervals always yields a rising series and so satisfies the first whether or not the program used relative mode. Both errors name the specific argument to reconsider and ask for an issue where the program says the file is already being read as written.
